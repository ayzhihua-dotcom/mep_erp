## 一、业务决策（D-11，本轮新增，待业务确认）

| 编号 | 决策内容 |
| --- | --- |
| D-11 | **系统界面与单据默认语言为中文；葡语（pt-BR）、英语作为可选项，由用户在个人设置中自由切换。** 不强制全局三语同步交付，但数据层（材料名称等）保留三语字段能力（MDM-002），为后续葡方人员全面使用预留扩展。 |

决策影响面：

1. 首选交付语言=中文；葡语/英语覆盖范围按"界面标签 + 关键单据打印 + 通知"三条线分阶段推进。
2. 用户级语言切换采用 ERPNext 原生 User Language 设置，无需二次开发。
3. 三语验收标准相应调整为"切换能力可验证 + 中文完整性 100%"，葡/英覆盖允许分批补齐。

## 二、语言承载范围与优先级

| 层级 | 内容 | 默认语言 | 葡/英策略 |
| --- | --- | --- | --- |
| L1 界面标签 | ERPNext 原生界面 + 定制 DocType 字段标签、状态名 | 中文（zh） | po 文件翻译；P0 单据（MR/PO/Shipment/Import Case/收货/领料）优先，其余分批 |
| L2 单据打印模板 | PO、Shipment、Import 单证清单、领料单、盘点单 | 中文 | 关键对外单据（给供应商/海关/监管）出葡语或双语版本，随对应模块开发期交付 |
| L3 通知与预警 | 邮件/SMS/系统通知模板 | 中文 | 预警通知按接收人语言偏好发送（技术允许时），否则中文+关键摘要译文 |
| L4 业务数据 | 材料名称（MDM-002）、规格描述、单据备注 | 录入时三语字段并存 | 由业务维护；系统不自动翻译 |
| L5 报表/驾驶舱 | 指标名称、筛选器 | 中文 | 分批补葡/英翻译 |

## 三、技术实现方案

### 3.1 界面与 DocType 翻译（L1）

1. ERPNext 原生界面：直接使用官方 zh / pt / en 翻译包；版本核验时确认目标版本的中文翻译完整度（L-02 衍生检查项）。
2. 定制应用（cb_erp）：
   - 每个定制 DocType 的 Label/Description/状态 Option 直接用中文文本编写（默认语言即中文，所见即所得）。
   - `cb_erp/cb_erp/translations/pt.csv`、`en.csv` 承载葡/英翻译文件；未翻译字符串自动回退显示中文原文。
   - 导出机制：bench 端使用 getappstrings / 格式化 CSV，翻译文件纳入 Git 版本管理。

### 3.2 用户级语言切换

- User 表 `language` 字段；默认值设置为 `zh`（系统默认语言 System Settings 同步设为中文）。
- 新用户创建时默认中文；个人设置中可切换 pt-BR / en，立即生效，无需重新登录依赖项另行验证。

### 3.3 单据打印模板（L2）

- Print Format 名称带语言后缀（如 `Purchase Order - PT`），按使用场景选择；
- 对外单据（PO、Shipment 相关、Import 单证清单）支持中葡双语栏式模板（同一模板内并列两栏，避免维护两套）——是否采用双栏式待业务确认（P-T1）。

### 3.4 通知与预警（L3）

- Email Template / Notification 按模板维护中/葡两版；
- 预警通知：Alert Event 接收人绑定语言偏好字段（User 语言），发送时选择匹配模板，缺失该语言模板时回退中文。

## 四、三语名称（MDM-002）落地

- Item 增加自定义字段：`custom_item_name_zh`（默认原生 item_name 沿用中文）、`custom_item_name_pt`、`custom_item_name_en`。
- 录入激励而非强制：中文必填；葡/英可后补；预置报表显示三语完整率。
- 采购/物流单据打印时按模板语言选择对应名称字段（缺失时回退中文）。

## 五、验收要点（调整后口径，对应 D-11）

1. 新用户默认看到中文界面；个人设置切换葡/英生效且正确回退中文。
2. 中文覆盖完整性 100%（原生 + 定制全部可见标签）。
3. P0 单据的葡语翻译覆盖：MR/PO、Shipment、Import Case、收货登记、领料单五类界面标签可切换显示。
4. 至少一份对外单据（建议 PO）有中葡双语打印模板可输出。
5. 材料三语名称字段完整/回退机制可验证。
