- 编制依据：SRS V1.0、《ERPNext 标准能力核验与开发任务拆解》（V0.1）、《数据库关联与权限设计》（V0.1）、《ERP 模块功能清单与字段字典 V0.2》；回应 S0 阶段门遗留事项 L-01（D 决策冻结前提）、L-02（ERPNext 目标版本核验）。
- 编制日期：2026-10-28
- 状态：草稿（待业务/技术评审确认）

## 一、阶段定位与环境目标

- 阶段名称：S1 基础平台与权限。
- 本交付物目标：给出开发环境、测试环境、定制应用骨架的搭建方案，使后续任务包（TP-PRJ / TP-PUR / TP-LOGIMP 等）可直接进入开发。
- 环境原则：开发、测试、（后续）生产三套环境隔离；配置与代码可版本化；生产前不得在开发环境直接做财务数据演练。

## 二、ERPNext 目标版本选型（回应 L-02）

| 项 | 内容 |
| --- | --- |
| 选型原则 | 官方稳定版优先；新定制开发应基于当前稳定主版本线（避免新版本发布后立即面临强制升级）；版本冻结后 S1~S6 不再更换大版本 |
| 候选版本 | ERPNext v15 / v16 系列稳定版（具体小版本，须在环境搭建时以官方 GitHub Release 与官方文档为准进行核验并冻结） |
| 核验清单 | ① Workflow（多级审批流）能力；② Quality Inspection 强制检验前置；③ Landed Cost Voucher 分摊能力；④ Stock Reconciliation/盘点流程；⑤ 多语言与多币种（BRL/CNY）；⑥ Meeting/Project 相关能力；⑦ Bench/frappe-docker 的部署与升级路径 |
| 冻结动作 | 环境搭建完成后，写入《S1 交付物补充：版本核验记录》，作为 S1 验收条件之一 |

> 注：本草案编制时在线核验不可用，故按"候选主线 + 搭建时官方渠道冻结"处理，不预先锁死小版本。

## 三、环境构成方案

### 3.1 开发环境（Dev）

| 项 | 方案 |
| --- | --- |
| 部署形态 | frappe-docker（Docker Compose）或 Bench（Linux）；优先 frappe-docker，便于新机重建与升级演练 |
| 数据库 | MariaDB（ERPNext 官方默认）+ Redis（队列/缓存/Socker） |
| 仓库 | 代码仓库（Git）：定制应用独立仓库；配置变更以补丁/fixture 导出并纳入版本管理 |
| 访问 | 内网可访问；管理员账号独立；启用开发者模式仅限 Dev |

### 3.2 测试环境（Test）

| 项 | 方案 |
| --- | --- |
| 部署形态 | 与 Dev 同形（frappe-docker / Bench），独立实例 |
| 数据 | 使用已脱敏的模拟业务数据；配置/补丁沿 Dev→Test 迁移 |
| 用途 | UAT 预演、任务包验收测试、权限与数据范围测试、升级回归 |

### 3.3 生产环境（Prod）——本阶段只规划，不搭建

| 项 | 方案 |
| --- | --- |
| 部署形态 | 由业务方确认（自托管服务器 / 云主机 / Frappe Cloud），S4 前冻结 |
| 关键要求 | 独立于 Dev/Test；备份与恢复见第六节 |

## 四、定制应用骨架（Custom App）

### 4.1 命名建议（待确认）

| 项 | 建议 |
| --- | --- |
| 应用名 | `cb_erp`（中国—巴西 ERP 定制应用；示例，业务方可更名） |
| 安装目标 | 站点（site）级安装；所有定制 DocType 均放入该应用 |
| 结构 | per DocType 文件夹；fixtures 导出 Custom Fields/Workflow/Print Format/Email Template；translations 放入应用以承载三语 |

### 4.2 定制对象清单（承接《数据库关联与权限设计》）

第一优先（S2 前完成骨架创建，字段先行）：

1. Design BOM（含 Design BOM Item 子表）
2. Design Change Request（含版本差异行）
3. Project Material Requirement（含需求行）
4. Shipment / Shipment Item / Shipment Document
5. Import Case / Import Document Checklist / Import Cost / Import Cost Allocation / Import Milestone

第二优先（S3~S5 前完成）：

6. Material Issue Plan（现场领料计划）
7. Supply Chain Exception（供应链异常）
8. Alert Event（预警事件）
9. proj 相关 Custom Fields（Project：合同编号、合同金额、预算金额、预算币种、状态扩展）

## 五、组织与角色骨架（S1 第二交付物衔接衔接点）

- Company：中国采购主体 + 巴西项目主体 +（待确认）本地运维主体；基准币种、会计年度配置。
- 角色（Role）初版清单（细化矩阵见 S1 第二交付物）：系统管理员、工程人员、中国采购、巴西采购、物流人员、清关人员、仓库人员、项目经理、财务人员、管理层。

## 六、备份与恢复方案（草案）

| 环境 | 备份内容 | 频率 | 保留 |
| --- | --- | --- | --- |
| Dev | 全库 backup（`bench backup --with-files`） | 手动 + 关键节点 | 最近 3 份 |
| Test | 全库 backup | 每日 + UAT 前 | 最近 7 份 |
| Prod（规划） | 全库 + files + 配置/补丁仓库 | 每日增量/每周末全量 | 按业务方保留政策 |

- 恢复演练：Test 环境每阶段末执行一次恢复演练并记录；未演练通过不得视为备份可用。

## 七、S1 验收要点（本交付物）

1. Dev/Test 环境已搭建并可访问；管理员账号与测试用户示例可登录。
2. 定制应用骨架已创建并安装到站点；fixtures 机制可用。
3. 版本核验记录完成（L-02 关闭）。
4. 备份与恢复在 Dev/Test 已执行至少一次且可恢复。
