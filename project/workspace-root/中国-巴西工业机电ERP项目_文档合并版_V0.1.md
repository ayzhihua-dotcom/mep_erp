## 十、界面设计原则与界面功能点（UI/UX）

### 设计原则

1. **简单易用**：后台默认安全；主操作一键完成；减少录入字段，默认自动带出；关键操作有明确反馈。
2. **现代科技化**：统一设计系统；信息架构清晰；驾驶舱可视化；移动端轻量操作模式。
3. **PC + 移动端**：PC 端标准业务表单；移动端扫码/列表领料、到货登记、清关状态、预警通知。

### 界面功能点

1. **PC 端**：采购订单、进口案件、成本、盘点、预警等标准表单；后台安全默认。
2. **移动端**：扫码/列表领料、到货登记、清关状态查看、预警通知接收（数据范围与权限一致）。
3. **BI 驾驶舱**：供应链、库存、成本、项目视图（承接 BI-001；指标口径与 CST/ALR 一致）。
4. **多语言**：界面、按钮、模板、通知、格式（SRS 九、九.1）。

### 界面验收要点

- 移动端权限与数据范围一致；
- 驾驶舱指标与成本/预警统计口径一致；
- 三语界面输出可验证。

## 三、关键实体关系与唯一约束

1. **Project**：项目 → 区域/专业系统/工作包；关闭后只读历史，重开需审批（PRJ-007）。
2. **Material Requirement**：材料、规格、需求数量、需求日期、设计版本；净采购缺口计算留痕（PUR-002）。
3. **Purchase Order**：订单头 + 订单行；项目分配通过订单行项目分配独立记录，支持多项目、一行多项目（PUR-007；V1.0 §7.2）。
4. **Shipment**：Shipment ↔ PO Item 多对多，通过 Shipment Item 实现；一 PO 行可分多次发运，一批次可合并多个 PO 行（LOG-002/003；V1.0 §7.1/7.3）。
5. **Import Case**：案件关联装运批次与费用；清关放行/提货/收货为三事件（IMP-008；V1.0 §5.2）。
6. **Stock Ledger**：库存余额 = 交易流水汇总，禁止独立修改（INV-004；V1.0 §7.2/7.3）。
7. **Project Cost**：费用分摊明细与原始费用可核对；同一费用不得重复计入（CST-008；V1.0 §5.3）。

## 四、唯一约束

1. Project ID 唯一、受控维护。

3. PO Number 唯一；订单行可追溯来源申请/报价。
4. Shipment ID 唯一；Shipment Item 按（Shipment, PO Item）累计唯一，防重复关联。
5. Import Case ID 唯一；Import Cost Allocation 每笔费用唯一，不得在 Import Cost 与分摊中重复入账。

- 纳入 S0 阶段门蓝图所需的端到端主流程与关键子流程。

## 二、端到端主流程 BPMN（节点与流向描述）

**主流程泳道**：泳道 1（设计/工程）→ 泳道 2（采购）→ 泳道 3（物流/清关）→ 泳道 4（仓储/领料）→ 泳道 5（成本/管理）。

1. **启动**：设计/工程人员提交设计材料清单（PRJ-003，状态：草稿 → 已提交 → 审核 → 锁定）。
2. **需求生成**：由设计清单生成需求；需求数量 = 设计数量 × (1 + 损耗率)（PRJ-005）；需求汇总/缺口（PUR-002/DEM-001）。
3. **采购**：需求 → 采购申请/询价/比价 → 审批 → 采购订单（PUR-001~007）。
4. **装运/物流**：采购订单 → 装运批次/分批发运/包装/运输节点（LOG/SHP）。
5. **进口清关**：装运/采购 → 进口案件 → 单证清单 → 申报/查验/补资料/放行/提货 → 归档（IMP）。
6. **收货/入库**：清关/订单 → 收货检验 → 正式入库 → 库存交易（INV/WH）。
7. **领料**：正式入库 → 领料计划/批准 → 领料出库（INV/WH）。
8. **成本/管理**：进口费用 → 分摊 → 项目成本 → 预算偏差 → 预警/驾驶舱（CST/ALR/BI）。
9. **关闭**：项目关闭检查（PRJ-007）→ 关闭/退回。

## 三、子流程

1. **设计变更子流程**：PRJ-004；不覆盖旧版本；已下单/发运减量生成影响清单。
2. **采购订单变更/关闭子流程**：PUR-008/009；审批后改单重审批；关闭校验。
3. **分批发运/合并子流程**：LOG-002/003；一 PO 行分批、一批次多 PO 行。
4. **清关事件子流程**：IMP-008；放行/提货/收货三事件区分。
5. **库存调拨/盘点/追溯子流程**：INV-007~012。

## 四、流程节点与触发

- **触发**：外部触发（设计提交、供应商确认、清关节点）；内部触发（业务动作、审批、计算）。
- **异常**：运输异常、清关异常、缺口/超预算 → 预警（ALR）并流向中断/处理。

## 三、技术实现方案

### 3.1 界面与 DocType 翻译（L1）

1. ERPNext 原生界面：直接使用官方 zh / pt / en 翻译包；版本核验时确认目标版本的中文翻译完整度（L-02 衍生检查项）。
2. 定制应用（cb_erp）：
   - 每个定制 DocType 的 Label/Description/状态 Option 直接用中文文本编写（默认语言即中文，所见即所得）。
   - `cb_erp/cb_erp/translations/pt.csv`、`en.csv` 承载葡/英翻译文件；未翻译字符串自动回退显示中文原文。
   - 导出机制：bench 端使用 getappstrings / 格式化 CSV，翻译文件纳入 Git 版本管理。

### 3.2 用户级语言切换

- User 表 `language` 字段；默认值设置为 `zh`（系统默认语言 System Settings 同步设为中文）。
- 新用户创建时默认中文；个人设置中可切换 pt-BR / en，立即生效，无需重新登录依赖项另行验证。

### 3.3 单据打印模板（L2）

- Print Format 名称带语言后缀（如 `Purchase Order - PT`），按使用场景选择；
- 对外单据（PO、Shipment 相关、Import 单证清单）支持中葡双语栏式模板（同一模板内并列两栏，避免维护两套）——是否采用双栏式待业务确认（P-T1）。

### 3.4 通知与预警（L3）

- Email Template / Notification 按模板维护中/葡两版；
- 预警通知：Alert Event 接收人绑定语言偏好字段（User 语言），发送时选择匹配模板，缺失该语言模板时回退中文。

## 四、恢复流程（标准操作，Dev/Test 适用）

1. 确认恢复目标：整体回滚（回站）/ 部分（仅数据）。
2. 准备：停止访问；如为容器，暂停应用进程但不卸载站点。
3. 执行：`bench restore <backup-sql>` + files 解压至 site files 目录。
4. 验证：站点启动、登录示例用户、抽查主数据（公司/仓库/材料各一条）与最新一张交易类单据。
5. 记录：填写《恢复演练记录》模板（第五节），归档至运维目录。

## 二、块 A：需求汇总（PRJ-006 / PUR-002）

### 2.1 计算口径（承接 V0.2 PRJ-006 条目）

```
需求总量 = Σ(设计数量 × (1 + 批准损耗率))       [Detail BOM 行]
已领用量 = Σ领料出库(项目+Item)                  [轿法: Stock Entry MI 行]
已分配量 = Σ已批准 MR 未完全转单量               [MR 行]
可用库存 = 项目现场仓可用数量               [Bin/Stock Ledger]
确认在途 = Σ装运已发运未到货 + 已批准 PO 未发运(采购承诺口径, 二选一可配置)
净采购缺口 = max(0, 需求总量 − 已领用 − 已分配宏大名额 − 可用库存 − 确认在途 + 其他占用纠正)
```

> 全部口径在计算服务中为**可注释参数**（损耗率默认值、"其他占用纠正"开关）；D-v1 决策冻结后默认值落锅。

## 二、框架设计

### 2.1 Alert Event（统一对象）

| 字段 | 规则 |
| --- | --- |
| alert_type | 缺料 / 交期违约 / 供应商逾期 / 单证缺失 / 放行未提货 / 超预算 / 超领 / 盘点差异 / 冻结/在途超时 / ETA 延误（承接 S2~S4 全部占位） |

- 同类型 + 同对象 + 未关闭 → 更新数值而非新建；同项目同类多对象可合并为一条汇总预警（明细子行）。

### 2.3 调度

- 调度：ERPNext 定时；需求密集点建议每 15 分钟计算（按规则不同节拍）；
