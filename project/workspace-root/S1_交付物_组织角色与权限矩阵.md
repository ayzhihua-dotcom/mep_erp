# 《S1 交付物：组织、角色与权限矩阵落地》草案（V0.1）

- 编制依据：SRS V1.0（第 8 节权限）、《数据库关联与权限设计》（V0.1 第 5/6 节）、《ERP 模块功能清单与字段字典 V0.2》、《S1 交付物：环境搭建与定制应用骨架方案》（V0.1）。
- 编制日期：2026-10-28
- 状态：草稿（待业务方评审确认；角色人员名单待业务方提供）

## 一、定位与实现机制

### 1.1 定位

- 将《数据库关联与权限设计》中的 RBAC 原则，细化为 ERPNext 中**可直接配置**的：组织/主数据结构、角色清单、模块权限矩阵、数据范围规则、内控分离规则。
- 本交付物完成后，S2 之前须在 Test 环境完成首轮配置验证。

### 1.2 ERPNext 实现机制映射

| 权限需求 | ERPNext 机制 |
| --- | --- |
| 模块/单据级权限 | Role + DocPerm / Custom DocPerm |
| 数据范围（公司/仓库/项目） | User Permission（reference_doctype = Company / Warehouse / Project，apply to 指定 DocType） |
| 角色组合管理 | Role Profile（一人多角色场景统一打包） |
| 审批动作控制 | Workflow（文档状态迁移按 Role 限定 allowed 行为） |
| 字段级保密（如成本） | 表单 Form Load 限制 / 报表独立权限 / Print Format 权限（必要时定制开发） |
| 审计 | Versioning（文档变更历史）、操作日志、关键 DocType 启用 track_changes |

## 三、角色清单（10 类，SRS §8）

系统管理员（SYS）、工程人员（ENG）、中国采购（PRC）、巴西采购（BRA）、物流人员（LOG）、清关人员（CUS）、仓库人员（WHS）、项目经理（PM）、财务人员（FIN）、管理层（MGT）。

> 一人可兼任多角色（通过 Role Profile）；以下矩阵按"角色具备的能力"定义，实际人员范围由业务方提供名单后配置。

## 五、数据范围规则（User Permission）

| 角色 | 公司范围 | 数据范围附加规则 |
| --- | --- | --- |
| ENG | C2 | 按 Project 限定（仅其参与项目） |
| PRC | C1 | PO/MR 按 Project 限定；不授权 C2 仓库数据 |
| BRA | C2 | 按 Project 限定；不授权 C1 单据 |
| LOG | C1 | 装运/进出口日志按 Shipment 限定 |
| CUS | C2 | 按 Import Case 限定 |
| WHS | C2 | 按 Warehouse 限定（含子仓） |
| PM | C2 | 按其分管 Project 全链可见 |
| FIN | C1+C2 | 财务域全量；采购/库存域只读 |
| MGT | C1+C2 | 全域只读 + 驾驶舱 + 预警审批 |
| SYS | 全部 | 全量；操作全部进入审计 |

规则：User Permission 空置 = 无该类型数据访问（默认拒绝）；跨公司操作（如 C1 采购供 C2 项目）通过 PO 项目分配记录（PUR-007）关联，不以放宽数据范围实现。

## 六、内控分离与敏感操作规则

| 编号 | 规则 | 实现机制 |
| --- | --- | --- |
| IC-01 | 审批人与付款审批人分离 | Workflow 赋予不同 Role；Payment Entry 增设付款审批节点（FIN 分离角色） |
| IC-02 | 收货人不得无授权修改采购价格 | PO 对 WHS 只读；发票核价归属 FIN/A |
| IC-03 | 盘点人不得独立完成重大差异审批 | Stock Reconciliation 差异 > 阈值 → 二级审批（PM/FIN），提交人不可自批 |
| IC-04 | 进口费用变更须记录原金额/新金额/原因 | Import Cost 强制字段 + track_changes + 变更审批流 |
| IC-05 | 汇率覆盖、成本分摊调整、主数据合并、状态豁免须留痕并授权 | ALR-006 审计事件清单；对应操作限定 SYS/FIN+A |
| IC-06 | 冻结库存只可由受控角色解冻 | INV-011；冻结状态 Workflow 限定 WHS 加冻 / PM+F 解冻 |
| IC-07 | 已批准 PO 改单须重新审批并保留版本 | PUR-006/007；Workflow + Versioning |
| IC-08 | 关键单据不可物理删除 | DocPerm 取消删除权除 SYS 外；SYS 删除保留日志 |

## 七、认证与审计要求

- SYS、FIN 及持有审批权角色：启用强制强口令策略（+ 待确认是否启用双因素，取决于部署形态决策 O-01）。
- 全部关键 DocType 开启 track_changes；审批、状态变更、汇率覆盖、数量更改、成本分摊、主数据合并、状态豁免六类事件纳入审计报表（ALR-006）。
- 会话超时、登录失败锁定阈值：随版本核验记录一并确认（L-02 衍生）。

## 八、验收要点（S1 第二交付物）

1. 10 类角色在 Test 环境完成配置，且矩阵表中每一格可给出对照的 Role/DocPerm/User Permission 配置项。
2. 隔离基线三条（PRC/BRA 隔离）+ IC-01~IC-08 全部有配置或开发承载，并在 Test 环境用示例用户验证通过。
3. 权限矩阵经业务方签字确认后冻结为 S1 基线；后续变更走本文件修订。
