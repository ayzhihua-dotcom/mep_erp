## 二、审批工作流（PUR-006）

### 2.1 Workflow 设计（承接 IC-01 / PUR-006 验收要点）

| 要素 | 方案 |
| --- | --- |
| 状态 | 草稿 → 待审批（Submitted）→ 已批准 → 生效（含后续：部分到货 → 已关闭，收尾任务承接） |
| 审批阈值 | `custom_approval_threshold`：按 PO 总额分档（金额待定 D-y9）。默认三级结构：单笔 < A 档：采购主管；A~B 档：采购经理；> B 档：管理层 |
| 预算超限分流 | 行/汇总超出项目材料预算 → 追加审批节点（项目经理 → 财务），并行或串行待业务确认 |
| 指定人员审批 | 特定类目（如高价值设备、常规大宗材料）可配置指定审批人清单（主档配置机制，承接"指定人员审批"） |
| 分离校验 | 审批人 ≠ 制单人（服务端校验）；付款审批进一步分离（PR 付款单属财务，FIN 角色） |

### 2.2 改单与重审批（IC-07）

| 规则 | 实现 |
| --- | --- |
| 已批准 PO 修改核心字段（数量/单价/交期/供应商） | 触发重新审批流：版本备份（track_changes）→ 状态回退"待审批"（保留"改单标记"字段与原因输入框）→ 审批通过后恢复"已批准" |
| 修改记录留痕 | 修改前后值 + 修改人 + 时间（Version 承载）+ 修改原因必填字段 |
| 收货已发生后再修改 | 允许但强提示：仅可改"未收货/未下单扣减"部分；已收货行禁止减量（差异走 INV 退货流程而非改单） |

## 三、采购订单（PUR-007）

### 3.1 主表与行字段

| 区 | 字段 | 说明 |
| --- | --- | --- |
| 主表 | supplier / company / currency / conversion_rate / transaction_date / schedule_date | 标准字段；币种来源 MR（C1=CNY，C2=BRL） |
| 主表 | Incoterm / Incoterm 城市/目的港口 | 国际采购域预配置（LOG 域开发前先有占位） |
| 主表 | 目标仓库 set_warehouse | 按 MR 目的仓默认带出 |
| 主表 | 订单总额 / 税域 | PRC/BRA 分组的税域规则（税贡献：BRA 端合规性依赖本地发票模块对接，属 LPO 域任务，本任务字段预留） |
| 行 | item_code / qty / rate / tax / uam / schedule_date | 标准 |
| 行 | source MR / RFQ / SQ 追溯 | 标准字段承接 MR 关联；**Quotation 来源**：PO 行来源于报价（标准"Create PO from Supplier Quotation"功能承接；定制校验：PO 行必有关联 MR 行或经例外审批） |
| 行 | WBS / 工程系统 | 行级归属；与 MR 行来源一致 |

### 3.2 追溯链完整性校验

| 校验 | 规则 |
| --- | --- |
| L1 | PO 行 → MR 行（必选；例外：无需求直接下单须高权限 + 例外原因留痕，配置开关待业务确认） |
| L2 | PO 行 → SQ 行（建议；未从报价创建时标记"无报价采购"并计入后续绩效/审计报表） |
| L3 | 回溯链路一键钻取：PO 行 → 选定 SQ → RFQ → MR → Design BOM 版本/行 |

### 3.3 项目分配记录（独立记录）

| 项 | 方案 |
| --- | --- |
| 需求来源 | V0.2 PUR-007 条目："订单可服务多个项目；一行可服务多个项目" |
| 实现方案（建议默认） | 独立子表/独立单据 Purchase Order Project Allocation：`po + po_item + project + allocated_qty + allocation_ratio(可分比例)` |
| 校验 | 行累计分配量 ≤ 行数量；与 MR 项目口径一致（跨项目调解须留批准记录） |
| 下游 | Cost 承接（CST-002 承诺金额按项目套取）；Shipment/收货按分配量回算项目（TP-LOGIMP/INV 协调） |
| 与行级 project 字段的关系 | 行级 project 字段保留为"主项目"快捷字段；分配记录作为真实项目归属规则来源（二选一以避免双口径，开发启动会确认） |
